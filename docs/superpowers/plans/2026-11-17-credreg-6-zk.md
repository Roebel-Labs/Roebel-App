# Credential Register 6 — Zero-Knowledge Membership Proofs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a holder prove "I hold credential type X" without revealing which holder they are (spec 5.3, private proof level 2): one anonymous Semaphore group per credential type, a proof made on the phone, checked on chain or by a node route, with a per-scope nullifier so a mini app or a members-only vote can count each person once.

**Architecture:** A new contract `CredentialGroups` is the admin of one group per credential type in the **canonical Semaphore v4 deployment already on Gnosis** (`0x8A1fd199516489B0Fb7153EB5f075cDAC83c693D`, code present 2026-11-17). It reads `CredentialRegistry` (plan 1) and needs no change to it. Two ways in: a holder whose credential is public joins on chain from their own account (trustless, the account is public anyway); a holder whose credential is private hands an identity commitment to the node, which checks the private proof and adds the commitment through a maintainer key, so no on-chain trace links the account to the group. Leaving is driven by the register: anyone can evict a public member who no longer `holds`; the node evicts private members on revocation, renouncement-to-new-identity and expiry. The phone proves inside a hidden WebView with snarkjs (Hermes has no proven WebAssembly path, and no new native module is allowed), after a gating measurement on a low-end Android.

**Tech Stack:** Solidity ^0.8.28, `@semaphore-protocol/contracts` 4.14.2 (already a dependency of `contracts/governor-contract`), Hardhat + fork tests; `@semaphore-protocol/identity`, `@semaphore-protocol/group`, `@semaphore-protocol/proof` pinned at **4.14.2** (≥ 4.13.0 is required: soundness fix) in `packages/credential-registry`, `apps/web` and the WebView bundle; react-native-webview 13.16.1 (already in the binary); viem.

**Spec:** `docs/superpowers/specs/2026-11-17-credential-register-design.md` section 5.3 ("Private proof, two levels"), 8. Contract it builds on: `docs/superpowers/plans/2026-11-17-credreg-1-contract.md` ("The interface", "Forward compatibility with zero-knowledge proofs"). Server and app pieces it extends: plans 2 (Task 8 `holder.ts`), 3 (Task 1 wiring, Task 2 `held.ts`). Background read: `docs/SEMAPHORE_README.md`, `docs/SEMAPHORE_USAGE_GUIDE.md` and `contracts/governor-contract/contracts/semaphore/CitizenRegistry.sol` — an earlier Base-era prototype (owner-added commitments, browser identities). It is **not compiled** (outside `paths.sources`) and is not reused; its lesson is that an owner-maintained group is a trust point, which this plan limits to private joins only.

**How proofs are made on the phone today:** they are not. The MACI client (`apps/expo/lib/maci.ts`, `maci-key-derivation.ts`, `maci-crypto` 2.5.0) only derives BabyJubjub keys and encrypts ballots; the coordinator produces the proofs. This plan introduces the first on-device prover, which is why Task 1 is a measurement gate.

**Depends on:** plans 1–3 (and 4 for badge groups to matter). No redeployment of `CredentialRegistry` (plan 1 states this).

## Open questions for the owner

1. **Who maintains private members.** *Default: one node maintainer key (`CREDENTIAL_GROUPS_MAINTAINER_KEY`, set as `maintainer` by the contract owner), which can only add and remove commitments, never touch the register. Its honesty is checkable from outside only in aggregate: the node publishes every group's commitment list, and anyone can check that a group is never larger than the number of live holdings plus live accepted private invitations the node reports. Alternative: per-org maintainers appointed by each org, which spreads the trust but needs every org to run or delegate a key.*
2. **How long a removed member can still prove.** Semaphore accepts proofs against earlier roots for `merkleTreeDuration`. *Default: 1 hour for every group.*
3. **Which types get a group.** *Default: every type including Citizen, Attester and Guest, created on the first join. Citizen gives an anonymous "I am a citizen" proof; the existing MACI voting is not changed by this plan.*
4. **Proving-time bar.** *Default: on the reference low-end Android (Task 1) a proof for a group of up to 1,024 members must take at most 10 s at the median and 20 s at the 95th percentile, without the app being killed. If the bar is missed, stop after Task 1 and decide between a native prover in a store build and server-assisted proving (which weakens the anonymity against the node).*
5. **Identity per type.** *Default: a different Semaphore identity per account, type and version (derived from one secret), so a commitment never appears in two groups and a public-turned-private holder rejoins with a fresh identity.*

## Review Focus

1. **A holder switches public → private.** Expected: their public commitment is evicted (they no longer `hold`), and their private rejoin uses identity version + 1, so the old public commitment and the new private one are unrelated. Test in Tasks 2 and 6.
2. **A revoked member proves within the root window.** Expected: possible for at most `merkleTreeDuration` after removal, never after; the node removes within one sync cycle. Test in Tasks 2 and 4.
3. **The same person proves twice for one poll.** Expected: identical nullifier for the same scope, different nullifiers for different scopes; verifiers that count must reject the repeat. Test in Tasks 3 and 5.
4. **The node is asked to add a commitment for a credential the caller does not hold privately** (revoked, expired, someone else's leaf). Expected: refused. Test in Task 4.
5. **The proving WebView is killed or times out on an old phone.** Expected: a German error with "Erneut versuchen", no hang, no app crash. Test in Task 6.

**Interfaces:**

```solidity
contract CredentialGroups is Ownable2Step {
    ISemaphore public immutable semaphore;
    ICredentialRegistry public immutable registry;      // holds, isTypeActive, typeExists (plan 1)
    address public maintainer;                           // private joins; set by owner
    uint256 public constant MERKLE_TREE_DURATION = 1 hours;

    mapping(bytes32 => uint256) public groupIdOf;        // typeId → Semaphore group id + 1 (0 = none)
    mapping(bytes32 => mapping(address => uint256)) public publicCommitmentOf;   // typeId → account → commitment
    mapping(bytes32 => mapping(uint256 => bool)) public isPrivateMember;        // typeId → commitment

    constructor(address initialOwner, ISemaphore semaphore_, ICredentialRegistry registry_, address maintainer_);
    function joinPublic(bytes32 typeId, uint256 commitment) external;           // registry.holds(typeId, msg.sender); one per account per type
    function evictPublic(bytes32 typeId, address account, uint256[] calldata siblings) external;   // anyone, when !registry.holds(typeId, account)
    function leavePublic(bytes32 typeId, uint256[] calldata siblings) external; // the member themselves, any time
    function addPrivate(bytes32 typeId, uint256[] calldata commitments) external;                 // onlyMaintainer; type must be active
    function removePrivate(bytes32 typeId, uint256 commitment, uint256[] calldata siblings) external;   // onlyMaintainer
    function setMaintainer(address m) external;                                  // onlyOwner
    function groupOf(bytes32 typeId) external view returns (bool exists, uint256 groupId);
    function scopeFor(bytes32 typeId, string calldata appScope) public view returns (uint256);
    function verifyFor(bytes32 typeId, string calldata appScope, ISemaphore.SemaphoreProof calldata proof) external view returns (bool);
    function validateFor(bytes32 typeId, string calldata appScope, ISemaphore.SemaphoreProof calldata proof) external;   // consumes the nullifier in Semaphore (for on-chain counting, e.g. a members-only vote)

    event GroupCreated(bytes32 indexed typeId, uint256 groupId);
    event PublicJoined(bytes32 indexed typeId, address indexed account, uint256 commitment);
    event PublicLeft(bytes32 indexed typeId, address indexed account, uint256 commitment, bool evicted);
    event PrivateAdded(bytes32 indexed typeId, uint256[] commitments);
    event PrivateRemoved(bytes32 indexed typeId, uint256 commitment);
    event MaintainerSet(address maintainer);
    error NotHolder(); error StillHolder(); error AlreadyJoined(); error NotJoined(); error NotMaintainer();
    error TypeInactive(bytes32 typeId); error UnknownType(bytes32 typeId); error CommitmentInUse(uint256 commitment);
}
```

Rules: the group is created on the first join with `semaphore.createGroup(address(this), MERKLE_TREE_DURATION)`; a commitment may be in a type's group only once across both paths (`CommitmentInUse`); `verifyFor` returns false for an inactive type (org revoked, type retired) even if the root is fresh, and false when `proof.scope != scopeFor(typeId, appScope)`. There is deliberately no unscoped `verify`: every proof is bound to one app scope.

export async function zkJoin(d: Deps, c: Caller, p: { typeId: Hex; commitment: string; version: number }): Promise<Result<{ status: "pending" | "added" }>>;
export async function zkStatus(d: Deps, c: Caller, p: { typeIds: Hex[] }): Promise<Result<{ typeId: Hex; status: "none" | "pending" | "added"; version: number | null }[]>>;
export async function runZkMaintenance(d: ZkDeps): Promise<{ added: number; removed: number; evictedPublic: number }>;

Rules:
- `zk_join` only for a caller whose credential is **private** right now (plan 2 `holdings` says `private`); a public holder is told to join on chain (`409 USE_PUBLIC_JOIN`). One `added` or `pending` commitment per account and type; a new `version` replaces the old one (old row → `removing`).
- `runZkMaintenance`: add `pending` commitments in one `addPrivate` per type; remove (`removePrivate`, siblings computed from the published member list with `@semaphore-protocol/group`) every private member whose account no longer has a live private credential (revoked, batch revoked, expired, org or type inactive, or now public); call `evictPublic` for every `PublicJoined` account that no longer `holds`; skip with a log line when the maintainer balance is below 0.01 xDAI.

- `POST /api/credentials/zk/verify` (public, rate-limited 60/min per IP): checks the type is active on chain, the proof's root is the current root or one seen within `MERKLE_TREE_DURATION`, the scope equals `scopeFor(chainId, groups, typeId, appScope)`, then the snark. Returns the nullifier for the caller to count. Never stores or logs proofs.
